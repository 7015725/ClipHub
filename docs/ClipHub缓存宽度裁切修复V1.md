# ClipHub 缓存宽度裁切修复

## 真机现象

在 `20260806.01` 回归通过后，首页右侧内部控件出现裁切：

- 顶部关闭按钮只显示一部分。
- 卡片右侧翻译、复制、删除按钮被截断。
- 浮窗外框完整，系统返回和关闭行为基本正常。

## 根因

`ch_11_filter.js` 会缓存首页 View 树。标题按钮和卡片操作区的尺寸按构建时窗口宽度计算。

窗口隐藏后，如果共享几何保存了新的较窄宽度，下一次显示会直接复用旧 View 树：

1. WindowManager 使用新的窄宽度挂载窗口。
2. 缓存控件仍使用之前较宽布局的固定尺寸。
3. 数据未变化时不会重建页面结构。
4. 右侧固定尺寸控件超过当前窗口边界，产生内部裁切。

现有代码已经能在窗口显示期间收到 `onGeometryChanged` 后刷新布局；缺少的是“隐藏期间宽度变化，重新显示缓存窗口”的判断。

## 撤回的方案

已撤回以下未采用内容：

- `src/ch_17_adaptive_width_fix.js`
- `module-manifest-adaptive-width.json`
- `ClipHub_AdaptiveWidth_Test_Entry.js`

不增加第 17 模块。

## 当前测试方案

保持原有 16 个模块：

- 15 个原始模块。
- 已通过真机验证的 `ch_16_rapid_close_fix.js`。

测试入口升级为版本 8，模块集为 `20260806.04`。入口加载现有 `ch_11_filter.js` 时，仅在内存中加入以下判断：

1. 在挂载缓存窗口前记录旧的 `state.panelWidthPx`。
2. 将旧布局宽度与当前 `panelDimensions().width` 比较。
3. 差值超过 `touchSlop * 2` 时，将 `panelStructureDirty=true`。
4. 复用窗口完成挂载后，按当前宽度重建页面结构。
5. `ch_11_filter` 运行时模块版本标记为 39。

该测试不新增模块文件，也不改变模块数量。现有快速关闭防护继续生效。

## 测试重点

1. 当前窄宽度下顶部三个按钮完整显示。
2. 卡片四个操作按钮完整显示。
3. 放宽、缩窄、隐藏、重新显示后不恢复旧布局。
4. 首页系统返回和外部点击关闭保持正常。
5. 通过后再将同一逻辑正式折叠进 `ch_11_filter.js`。

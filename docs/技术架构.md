# ClipHub 技术架构

> 当前基线：`main` / module set `20260906.01` / Manifest Schema 2 / 20 个运行模块。

## 1. 运行环境

ClipHub 运行于 Android / ShortX / Rhino ES5，UI 使用 Android SDK 原生 View 与 WindowManager，不依赖 WebView。

运行时约束：

- Rhino ES5 only：禁止 `let`、`const`、箭头函数、`class`、模板字符串、可选链、空值合并和 `for...of`；
- 数据默认保存到 ShortX 目录下的 ClipHub 独立运行目录；
- UI、数据库、剪贴板监听和控制入口具有独立生命周期；
- Android 14 / ColorOS / ShortX 的窗口与 Back 行为以真机结果为最终依据。

## 2. 总体分层

```text
ClipHub.js
  ↓
module-manifest.json
  ↓
20 个 Rhino ES5 运行模块
  ├─ 基础设施：Base / Log / Database / Repository / Theme / Window / EventBus
  ├─ 业务能力：Clipboard / Classifier / List / Editor / Filter / Translation
  ├─ 页面宿主：UIShell
  ├─ 分词：TokenizerUI / TokenizerCore / TokenizerService
  ├─ 生命周期：VisibilityIntentGuard
  └─ 应用编排：App
```

入口负责远程同步、完整性校验、加载与失败回退；业务逻辑不得重新堆进入口文件。

## 4. 生命周期顺序

Manifest Schema 2 使用 `runtimeRole` 与 `lifecycleIndex` 约束初始化和关闭顺序。当前 managed 顺序为：

```text
Log → Database → Repository → EventBus → Theme → Clipboard → Window
→ List → Editor → Filter → Settings → Translation → UIShell
→ TokenizerService → VisibilityIntentGuard
```

`Base` 最先提供基础能力，`Classifier`、`TokenizerUI`、`TokenizerCore` 为 passive，`App` 负责最终应用编排。

关闭按确定性逆序执行；任何模块 `shutdown()` 都必须幂等并允许部分初始化状态。

## 5. 页面与导航架构

当前页面体系遵循 `ShortX_UI_Navigation_Contract_v2.md`：

- 页面定义唯一来源：`PageRegistry`；
- 页面历史唯一来源：`PageStack`；
- 业务导航唯一入口：`Navigator`；
- Back 决策唯一入口：`BackDispatcher`；
- 页面挂载统一进入 `UIShell` / Primary Window；
- 新增普通页面只注册 factory、parent 和 PageContract，不修改导航核心。

系统 Back、侧滑返回、Toolbar Back、Legacy Back、Predictive Back 和 IME First Back 必须收敛到同一状态机，一次 Back 最多弹出一层页面。

## 6. 数据与分页

主数据库 Schema 当前保持为 2。核心原则：

- UI 不直接写 SQL；
- Repository 是业务数据访问入口；
- 首页可以只读取长文本预览；
- 复制、输入、编辑、翻译和分词在真正执行时按 ID 获取完整正文；
- 支持 AJAX 追加、数字分页、懒加载、预加载和虚拟数据窗口；
- 正则高级筛选规则与分词规则使用独立存储体系。

## 7. 正则精确分词

正则精确分词不调用普通分词器。

成功结果必须满足：

1. 当前启用规则与临时正则产生候选完整匹配区间；
2. 临时正则固定最高优先级；
3. 重叠按“优先级 → 更长匹配 → 规则稳定顺序”裁决；
4. 命中和未命中区间都保留为可操作词块；
5. 所有词块顺序拼接后必须逐字符还原原文；
6. 无效正则与零宽匹配跳过并警告；命中超限或还原失败整次阻断。

## 8. 翻译

- 百度、有道：在 ClipHub 内显示结果；
- Google：通过 Android Intent 向 Google 翻译发送完整正文；
- Google 成功启动后隐藏 ClipHub UI；启动失败时保留 UI 并给出提示。

外部 Intent 的 UI 隐藏与恢复必须经过统一显隐意图和生命周期守卫。

## 9. WindowManager 与 ColorOS 安全边界

- `addView` / `updateViewLayout` / `removeViewImmediate` 必须在所属主线程执行；
- 所有关闭路径进入幂等清理链；
- 不允许关闭后残留透明遮罩或失效 View 引用；
- 颜色调用必须经过 `ClipHub.Theme` 安全桥，禁止直接把 Rhino 数字传入存在重载歧义的 Android 颜色 API；
- 发布前执行颜色审计，要求 `HIGH=0` 且 `WARN=0`。

详见 `ColorOS_Rhino颜色安全规范.md`。

## 10. 正式入口

正式用户入口只保留：

```text
ClipHub.js
tasks/ClipHub_全局剪贴板开关.js
module-manifest.json
```

`ClipHub.js` 维护后台实例；开关任务只负责显示/隐藏 UI，不停止数据库和剪贴板监听。

- Tokenizer regression suite；

自动化通过不替代真机验证。

# ClipHub 模块规范

> 本文描述 `main` 当前模块契约。历史 15 模块架构、旧开发分支和阶段性 Navigation 实现不再作为当前依据。

## 1. 唯一事实源

模块集合以根目录 `module-manifest.json` 为唯一机器可读事实源。当前：

```text
schemaVersion = 2
moduleSetVersion = 20260819.08
entryMinVersion = 8
sourceRef = main
modules = 20
resources = []
```

任何文档中的模块数量、SHA、Export 或生命周期描述与 manifest 冲突时，以 manifest 为准，并修正文档。

## 2. 仓库与运行目录

仓库：

```text
ClipHub/
├── ClipHub.js
├── module-manifest.json
├── src/
├── scripts/
├── tasks/
├── docs/
└── archive/
```

ShortX 运行目录：

```text
shortx.getShortXDir()/ClipHub/
├── modules/
├── data/
├── logs/
├── cache/
└── probes/
```

数据库、日志、下载缓存、运行锁和临时模块目录不得提交到 Git 仓库。

## 3. 入口职责

`ClipHub.js` 只负责：

- 环境与版本检查；
- 获取远程 manifest；
- 校验模块路径、Git blob SHA、Export、runtimeRole 与生命周期计划；
- 首次下载或版本变化时构建 staging 模块集；
- 完整校验后原子切换；
- 失败时恢复上一套可运行模块；
- 加载模块并启动 `App`。

禁止把业务页面、数据库查询、剪贴板处理或具体分词算法重新写进入口。

## 4. Manifest Schema 2

每个模块至少声明：

```text
name
path
sha
export
runtimeRole
```

managed 模块还必须声明唯一且连续的：

```text
lifecycleIndex
```

`runtimeRole` 当前允许：

- `base`：基础能力；
- `managed`：由生命周期计划初始化和关闭；
- `passive`：加载后提供纯能力，不参与 managed 生命周期序列；
- `app`：最终应用编排。

修改任意 `src/ch_*.js` 后必须同步对应 Git blob SHA，并在正式模块集合变化时提升 `moduleSetVersion`。

## 6. 命名空间与 API

模块必须挂载到 `ClipHub.<Export>`，禁止泄漏通用全局函数。

managed 模块应提供稳定的初始化/关闭边界，并满足：

- 初始化失败明确抛错或返回失败；
- `shutdown()` 幂等；
- 部分初始化状态也能安全清理；
- 不重复注册不可撤销的 hook；
- 不持有已经 detach 的 WindowManager View。

模块间通信优先经明确 API 或 EventBus，不通过跨模块修改私有状态完成。

## 7. 数据职责

- `Database`：SQLite 连接、结构、迁移；
- `Repository`：业务数据访问；
- `Clipboard`：系统剪贴板监听和回环抑制；
- `Classifier`：内容分类，不承担 UI 副作用；
- `Filter`：搜索、筛选与高级正则筛选；
- `TokenizerService`：分词规则状态与执行编排；
- 分词规则与高级筛选规则必须保持独立存储。

UI 模块禁止绕过 Repository 随意执行 SQL。

## 8. 页面与 Back 职责

页面导航遵循 Navigation Contract v2：

```text
PageRegistry  = 页面定义唯一来源
PageStack     = 页面历史唯一来源
Navigator     = 业务导航唯一入口
BackDispatcher= Back 决策唯一入口
UIShell       = 页面挂载与 Primary Window 宿主
```

新增普通页面时：

1. 注册页面 factory；
2. 声明 parent；
3. 声明 PageContract；
4. 通过 `Navigator.push()` 打开。

不得为了新增页面修改导航核心的硬编码 pageId 分支。

## 9. IME 与系统 Back

- `imeBackFirst=true` 时第一次 Back 只隐藏输入法；
- 焦点交还 Primary Window 并重新武装 Back；
- 第二次 Back 才执行页面 pop；
- Predictive Back 只在 commit 阶段改变页面栈；
- 同一次 Back 请求不得跨层连续 pop。

## 10. 生命周期与显隐

`VisibilityIntentGuard` 统一处理：

- 显示/隐藏意图；
- 延迟回调取消；
- 外部 Intent 后 UI 隐藏；
- hook 对称安装与卸载；
- shutdown 时 Handler/View/兼容回调释放。

任何模块不得在 UI 已明确隐藏后通过过期回调重新 attach 旧页面。

## 11. Rhino ES5

运行模块禁止使用：

```text
let
const
class
=>
模板字符串
可选链
空值合并
for...of
```

静态检查：

```bash
python3 scripts/validate_es5.py .
```

## 12. 发布检查

正式发布前执行：

```bash
bash scripts/release_preflight.sh --main
```

并完成真机验证。仅替换某一个 `src/` 模块而不同步 manifest 不属于受支持的正式发布方式。

## 2. 新增完整分词系统

### 2.1 分词入口与页面

- 首页长按剪贴板列表 chip，可直接对该条完整文本进行分词。
- 编辑页“来源 / 标签”区域增加分词入口，可对当前编辑文本进行分词。
- 分词页提供“普通分词”和“正则规则”两种模式。
- 打开分词页后自动执行当前模式，不要求再次点击开始按钮。
- 分词结果使用自适应词块展示；连续长 URL、长邮箱和普通长文本会按内容换行增高，不再受固定词块高度裁切。

### 2.2 词块选择和操作

- 单击词块切换选中状态。
- 在词块之间拖动可连续选择。
- 长按词块可进入更多操作。
- 底部统一提供复制、输入和编辑操作。
- 多个不连续词块按原文位置拼接，只连接所选词块原文，不自动插入空格、换行或其他字符。
- 正则命中词块和未命中词块具备相同的选择、复制、输入和编辑能力，仅通过样式区分来源。

## 3. 正则精确分词语义

正则模式新增 `regex-tokenizer-exact-v3` 路径。该路径不调用普通分词器，输出由正则匹配区间和原文未匹配区间共同组成。

### 3.1 区间生成

- 当前已勾选的分词规则与分词页临时正则共同参与匹配。
- 每次正则命中统一使用完整匹配区间；旧规则字段中的 `mode`、`keepDelimiter` 和 `groupMode` 不改变精确模式的区间结果。
- 所有命中区间独立成为词块。
- 所有未命中区间按原文位置连续保留，不丢弃、不重排，也不交给普通分词器二次切割。
- 非空原文没有任何命中时，整段原文作为一个未命中词块。
- 纯空格、换行和制表符词块以可见占位符显示，但内部仍保存原始字符。

### 3.2 重叠裁决

重叠或完全相同的候选区间按以下顺序裁决：

1. 规则优先级更高者优先；
2. 优先级相同时，匹配区间更长者优先；
3. 优先级和长度均相同时，使用规则管理页的稳定列表顺序；
4. 临时正则固定为最高优先级。

例如原文为 `abc`，规则 A 命中 `ab`、规则 B 命中 `bc`，两者优先级和长度相同，而 B 在规则列表更靠前，则保留 `bc`。

### 3.3 错误和安全边界

- 无效正则：跳过对应规则，并显示规则级非阻断警告。
- 零宽匹配：跳过该次命中，并显示规则级非阻断警告。
- 命中数量超过安全上限：整次分词失败，清空本次结果并显示阻断错误。
- 词块顺序、区间或拼接还原校验失败：整次分词失败，不展示可能缺失或乱序的结果。
- 成功结果必须满足：所有词块按顺序拼接后与输入原文逐字符完全一致。

## 4. 分词规则独立管理

分词规则使用独立的 `TokenizerService` 和独立存储命名空间，不与高级筛选的 `regex_rules` 表混用。

- 支持预制规则启用、停用和覆盖配置。
- 支持创建、编辑和删除自定义规则。
- 规则抽屉采用草稿选择，确认后才提交参与分词的规则集合。
- 支持规则标题、表达式、匹配/切割配置和稳定列表顺序。
- 最多保存 64 条自定义规则、同时选择 64 条规则。
- 规则标题最长 80 个字符，表达式最长 2048 个字符。
- 旧版规则状态可迁移到 Rule Schema 2，并保留备份路径。

## 5. 高级筛选正则规则

高级筛选继续使用数据库中的独立规则体系。本版本新增 `regex_rules` 功能表、索引和 Feature Schema 1：

- 规则包含标题、备注、表达式、flags、启用状态和稳定手动顺序。
- 标题规范化后保持唯一，避免大小写或空白差异造成重复规则。
- 支持规则列表、编辑、测试和返回链。
- 功能迁移只新增 `regex_rules` 表、索引和 `schema_meta` 版本记录，不改写现有剪贴板正文、标签或分页数据。

分词规则与高级筛选规则分别服务于“文本切块”和“列表筛选”，两者不会互相覆盖配置。

## 6. Google 翻译模式

设置页翻译模式新增 Google 翻译选项。

- 首页点击翻译后，读取对应剪贴板条目的完整正文。
- 优先尝试 Google 翻译文本处理入口，并提供包级 `PROCESS_TEXT`、`ACTION_SEND` 和应用启动入口回退。
- Google 翻译成功启动后关闭 ClipHub UI，避免悬浮窗遮挡翻译页面。
- 未安装 Google 翻译、文本为空或所有 Intent 均启动失败时，ClipHub 保持显示并给出非崩溃提示。
- 百度和有道仍使用 ClipHub 内置翻译结果页，不受 Google 模式的 UI 关闭逻辑影响。
- 增加 3 秒操作保护和运行状态统计，避免短时间重复启动。

## 7. Navigation Contract v2

新增 `UIShell`，将主要业务页面收口到单一 Primary Window 宿主，并建立以下唯一 Owner：

| 能力 | Owner |
| --- | --- |
| 页面定义 | `PageRegistry` |
| 页面历史 | `PageStack` |
| 导航动作 | `Navigator` |
| Back 决策 | `BackDispatcher` |
| Android Back 捕获 | `Navigation` |
| 页面挂载 | `UIShell` + Primary Window |

### 7.1 返回链统一

- Toolbar Back、页面返回、系统 Back、Legacy `KEYCODE_BACK` 和侧滑返回进入同一 Back 状态机。
- 一次 Back 请求最多弹出一层，避免重复回调导致跨页返回。
- 编辑页、标签页、设置页、正则规则页、翻译页和分词页使用统一页面栈。
- 修复“首页 → 分词 → 词块编辑 → 侧滑直接回首页”的跨层返回。
- 修复从分词页回到首页后，再次长按列表 chip 无法重新进入分词页的问题。

### 7.2 IME First Back

当页面合同启用 `imeBackFirst` 时：

1. 第一次 Back 只隐藏输入法，页面栈不变；
2. 焦点交还 Primary Window；
3. Back 捕获重新武装；
4. 第二次 Back 才执行页面返回。

### 7.3 Predictive Back

- `start` 阶段冻结页面栈快照。
- `progress` 只更新进度，不提前修改页面栈。
- `cancel` 清除会话并恢复视觉状态。
- `commit` 才执行一次 Back。
- 重复 `requestId`、过期会话或快照不一致时拒绝重复 pop，并记录诊断计数。

普通新页面只需向 `PageRegistry` 注册 factory、parent 和 PageContract，再调用 `Navigator.push()`；不应修改导航核心。

## 8. UI 与窗口生命周期修复

### 8.1 分词长文本显示

- 词块高度根据实际文本测量结果自适应。
- 连续无空格 URL 允许在词块内部换行。
- 复制、输入和编辑始终使用完整原文，不依赖当前可见文本范围。

### 8.2 Visibility Intent Guard

新增 `ch_20_visibility_intent_guard.js`，统一处理显示、隐藏和外部 Intent 后的 UI 生命周期：

- 延迟回调可取消，退出后不会再次 attach 旧页面。
- hook 安装和卸载保持对称。
- 重复初始化不会叠加 Back、Window 或生命周期监听。
- `shutdown()` 释放 Handler 回调、View 引用和兼容 hook。
- Google 翻译成功启动后的隐藏意图由 Translation 模块发出，Classifier 不再承担 UI 副作用。

### 8.3 页面重新进入

- 页面 mount/unmount 使用代次和当前宿主状态校验。
- 旧分词挂载失败或残留时先清理再恢复首页长按入口。
- 快速“显示 → 隐藏 → 显示”不会复用正在关闭的页面引用。

## 9. Manifest Schema 2 与启动契约

`module-manifest.json` 升级到 Schema 2。每个模块除 `name/path/sha` 外，还声明：

- `export`：模块导出的唯一名称；
- `runtimeRole`：`base`、`managed`、`passive` 或 `app`；
- `lifecycleIndex`：受管理模块的确定性初始化和关闭顺序。

入口启动流程会验证：

- Manifest Schema、入口最低版本和 `sourceRef`；
- 模块名称、路径、Git blob SHA、export 和运行角色；
- 生命周期索引连续且唯一；
- Base 首先加载、App 最后启动；
- 失败同步不会覆盖上一套可运行模块。

生产资源统一由 manifest 声明；当前版本 `resources=[]`，不存在未被运行时消费的附带资源。

- 主数据库 `SCHEMA_VERSION` 仍为 2，不迁移或清空现有剪贴板、标签和分页数据。

- Predictive Back 真机路径取决于 Android 与 ShortX 宿主是否提供对应 callback；不可用时继续使用 Legacy Back 路径。

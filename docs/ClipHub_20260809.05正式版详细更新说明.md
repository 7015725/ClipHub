## 3. 分页与数据读取更新

### 3.1 新增两种分页模式

首页列表现在支持：

- AJAX 增量追加：滚动接近底部时加载下一批数据，并保留当前位置。
- 数字分页：显示页码导航，可切换指定页面。

分页模式、每页数量和预加载开关可在设置页调整。每页数量允许 5～1000 条，默认 100 条。

### 3.2 新增懒加载与下一页预加载

- 根据剩余滚动距离触发下一批数据加载。
- 在空闲阶段预取下一页，减少触底后的等待时间。
- 查询条件变化时自动失效旧预取结果，避免不同筛选条件之间串页。
- 保留快速重置入口，可回到第一页最新位置。

### 3.3 首页只读取约 200 字符预览

`Repository16` 对首页列表查询增加 200 字符预览限制。完整正文只在复制、编辑、输入、翻译、详情等实际需要时按 ID 查询。

影响：

- 长文本不会在首页首次查询时全部进入内存。
- 大数据量下数据库读取、JS 对象构建和 View 绑定压力降低。
- 不改变数据库中保存的完整正文，也不改变复制、编辑和翻译结果。

### 3.4 新增虚拟数据窗口与异步水合

- 列表只维护当前位置附近的数据窗口和 View。
- 远离可视区域的数据块可脱水为轻量占位数据。
- 回到对应区域时，由单一工作线程重新读取和水合。
- 水合请求带有代次和查询签名，过期结果不会覆盖新页面或新筛选条件。

该能力沿用实施阶段已经确认的分页缓冲边界；最终 UI 与窗口安全修复没有继续扩大缓冲参数，也没有改变数据库事务语义。

## 4. 列表渲染与滚动性能更新

### 4.1 View 差量更新与 `CardHolder` 复用

- 同一数据范围内优先重绑已有 `CardHolder`，减少完整 View 重建。
- 根据卡片兼容键复用 Holder，避免不兼容的卡片结构被错误复用。
- 操作按钮引用与当前数据行重新绑定，避免复用后点击到旧条目。
- 标签颜色重绑失败时回退到完整卡片重建，不保留半更新状态。

### 4.2 分帧渲染

以下高开销场景改为分批执行：

- 首页首次虚拟窗口创建。
- AJAX 追加大量数据。
- 水合结果与当前窗口发生大范围重叠。
- keyed 重建与大量 Holder 替换。

首批渲染设置时间预算，后续批次通过主线程消息队列继续执行，降低单帧集中创建大量 View 导致的卡顿。

### 4.3 滚动锚点与零变化优化

- 数据新增、删除、置顶、标签变化和分页刷新时记录当前锚点。
- 刷新完成后按条目 ID 和偏移恢复位置。
- 数据与布局未变化时跳过重复布局和完整刷新。
- staged attach 期间发生滚动时，后续批次会重新计算目标范围，避免继续构建已经离开的区域。

## 5. UI 与交互更新

### 5.1 首页顶部拖动区域统一

首页顶部改为统一的可视拖动条，拖动区域和视觉提示保持一致，减少“看得到但拖不动”或“可拖动但没有提示”的差异。

### 5.2 设置页顶部间距修正

设置页顶部留白、拖动条与正文起始位置重新对齐，使其与首页及其他浮窗保持一致。

### 5.3 高级筛选抽屉改为事务替换

高级筛选抽屉重建流程改为：

1. 在旧抽屉仍可用时构建新抽屉。
2. 新抽屉成功加入后再移除旧抽屉。
3. 全部成功后提交新的 View 引用和选项映射。
4. 任一步失败时清理新抽屉并恢复旧抽屉。

同时增加重建代次、重复请求合并和滚动恢复身份校验，修复筛选变化时的闪帧、空白和滚动锚点漂移。

## 6. 浮窗生命周期与崩溃风险修复

### 6.1 统一异步移除窗口

`Window19` 新增 `ClipHub.Window.requestViewRemoval()`，详情、编辑器、筛选、设置和翻译窗口统一通过该入口移除。

主要行为：

- 始终通过主线程 `Handler` 排队执行 `WindowManager.removeView()`。
- 不再在正式模块中调用 `removeViewImmediate()`。
- 捕获关闭时的 `WindowManager`、根 View、角色和代次，避免异步回调读取已清空的全局引用。
- 同一 View 的重复移除请求会合并，不会重复调用 `WindowManager`。
- 通过 attach-state listener 确认最终脱离，并提供超时和失败状态。

### 6.2 关闭期间的重新打开采用“最后一次请求”

窗口关闭尚未完成时再次打开，不会立即复用正在移除的旧 View。系统只保存最后一次打开请求，确认旧窗口脱离后再创建或恢复新窗口。

该规则覆盖：

- 长文本详情页。
- 编辑/新增/标签编辑页。
- 筛选首页。
- 设置页。
- 翻译结果页。

移除失败时不会自动重开，避免旧窗口仍附着时叠加第二个窗口。

### 6.3 主线程判断修正

不再使用 Rhino Java 包装对象的 `Looper` 引用相等判断。Android 23 及以上优先调用 `Looper.isCurrentThread()`；其他情况比较主线程与当前线程 ID。

该修复覆盖 Window、Filter、Editor、Navigation、Translation、Settings 和 App 的同步主线程入口。

## 7. Rhino 与 ColorOS 颜色安全更新

- 正式 UI 的 `Paint`、文字颜色和背景颜色统一通过 `ClipHub.Theme` 安全入口应用。
- 移除 `setColor(int)`、`setTextColor(int)` 和 `setBackgroundColor(int)` 等 Rhino 歧义调用绕行。
- `Drawable.setColorFilter(ColorFilter)` 合同回调被明确识别为安全对象转发，不再误报为数值颜色调用。
- 颜色审计增加方括号签名检查，可识别 `view["setTextColor(int)"](...)` 等绕行写法。
- 审计和 ES5 校验都会展开 `Filter`、`Settings` 等压缩模块的真实源码，不再只检查外层加载器。

正式审计目标：`HIGH=0 WARN=0 SAFE=10`。

## 8. 离线自包含与发布校验更新

### 8.1 `Settings24` 改为离线自包含

设置模块的完整 ES5 源码直接压缩在模块文件内，并在运行时校验 SHA-256 后加载：

- 不依赖运行时网络下载设置页源码。
- 不依赖旧的缓存补丁或备份模块替换。
- 源码校验失败会直接报错，不执行不完整内容。

### 8.2 完善正式发布预检

`scripts/release_preflight.sh --current` 与 `--main` 会检查：

- 当前 Git 分支与 `module-manifest.json.sourceRef` 一致；正式发布固定为 `main`。
- `ENTRY_VERSION`、模块集版本和模块版本符合当前发布声明。
- 15 个模块的 Git blob SHA 与 manifest 完全一致。
- 压缩源码 SHA、Rhino ES5 语法和颜色安全审计通过。
- 正式源码不存在 `removeViewImmediate()`。
- 正式源码不存在旧的 `Looper` 包装对象引用比较。
- `Settings24` 外层加载器不包含运行时网络或 Stage2 缓存替换逻辑。

临时审计目录改用 `${TMPDIR:-/tmp}` 下的 `mktemp` 随机目录，并在退出时清理。

## 9. 状态诊断新增内容

App 状态结果新增：

- `windowRemoval`：安全移除请求、排队、完成、超时、失败、待处理数量及最后错误。
- `colorSafety`：主题安全颜色接口调用状态。
- 分页、预取、虚拟窗口、数据窗口、水合 Worker、滚动性能和分帧任务状态。
- 高级筛选抽屉替换失败阶段和筛选查询耗时计数。

这些字段只增加诊断可观测性，不改变剪贴板业务数据。

## 10. 兼容边界

本次更新明确未调整以下内容：

- 不修改 SQLite Schema，不迁移或清空现有数据。
- 不改变剪贴板监听、去重、敏感内容判断和分类语义。
- 不改变共享窗口几何、拖动、缩放、IME 避让的核心参数。
- 最终 UI 与窗口安全修复不再调整已经冻结的分页缓冲区和虚拟窗口参数。
- 不改变正式控制端点命令：`show`、`hide`、`toggle`、`status`、`stop`。
- 保持 Rhino ES5：仅使用 `var` 和 ES5 函数语法，不引入 `let`、`const`、箭头函数、`class` 或模板字符串。

由于 `ENTRY_VERSION` 已由 5 升至 6，不能只替换单个模块。应使用正式入口和 `module-manifest.json` 同步完整的 15 模块集合。

## 12. 发布结论

`20260809.05` 已作为 `main` 正式稳定基线。相对合并前版本，主要收益是：

1. 大数据列表由一次性构建升级为分页、虚拟窗口和异步数据水合。
2. 高频滚动和数据更新由完整重建升级为 Holder 复用、差量更新和分帧执行。
3. 长正文由首页完整读取升级为 200 字符预览与按需读取。
4. 高级筛选抽屉由先拆后建升级为带回滚的事务替换。
5. 浮窗关闭由同步立即移除升级为统一、可观测、可去重的异步安全移除。
6. Rhino/ColorOS 颜色接口、主线程判断和压缩源码审计形成正式发布闭环。

相关改动已整体快进合并到 `main`，正式入口与 manifest 均固定使用 `sourceRef=main`。功能分支保留作为已验证历史，不应单独回退或手工替换其中某个运行模块。

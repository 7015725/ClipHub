# ClipHub 结构性最小尺寸与底部底座修复 V13

## V12 真机结论

V12 启动身份正确，但视觉验收失败：

- 入口版本 12。
- 模块集 `20260806.05`。
- 模块数量 16，没有新增模块。
- 正常尺寸下卡片底部操作行可见。
- 缩到允许的最小尺寸后，顶部操作区、搜索和筛选仍不可用。
- 固定底座没有稳定占据可见布局高度。
- 窗口底边仍可能从卡片中间硬切。

## V12 最低尺寸补丁问题

原 `sharedPolicy()` 已定义：

- `minWidthDp=280`
- `minHeightDp=320`

V12 使用 `Math.max(policy.minWidthDp, 190)` 和 `Math.max(policy.minHeightDp, 300)`。结果仍然是 `280×320dp`，并没有提高实际缩放下限。

## V13 修复范围

V13 仍是加载期测试补丁，不新增模块、不修改标准模块清单：

- 测试入口版本 13。
- 继续使用 `module-manifest-rapid-close.json`。
- 模块集保持 `20260806.05`。
- 模块数量保持 16。
- `ch_08_window.js` 测试版本 21。
- `ch_11_filter.js` 测试版本 44。

### 共享几何策略

直接修改 `sharedPolicy()`：

- 最小宽度提高到 `330dp`。
- 最小高度提高到 `460dp`。

`computeGeometry()`、拖动缩放中的 `buildSharedGeometry()`、保存几何后的重新加载都会使用同一策略，不再只修改其中一个调用点。

### 窄窗口判断

紧凑模式优先使用已经提交的：

- `state.panelWidthDp`
- `state.panelWidthPx`

不再以可能仍是旧值的内部 View 测量宽度作为首选。紧凑阈值调整为 `360dp`。

### 底部布局

底部结构改为真实父级布局：

```text
panelRoot（垂直）
├── 顶部拖动条和搜索头部
├── bodyFrame，height=0、weight=1
│   ├── ScrollView
│   └── 24dp 渐变覆盖层
└── 30dp 实色底座
```

关键变化：

1. 实色底座直接添加到 `panelRoot`，不再放在 `buildResultArea()` 内部。
2. `bodyFrame` 的可用高度会真实扣除 30dp 底座。
3. 24dp 渐变直接添加到 `bodyFrame`，绘制顺序位于结果区之上。
4. 结果容器增加 52dp 底部滚动空间，使最后一张卡片可滚动到渐变上方。
5. 高级筛选页面不添加首页底座，避免覆盖筛选页固定按钮。

## 验证标准

1. 窗口不能缩到低于 `330×460dp`。
2. 最小尺寸下标题、顶部三个按钮、搜索和筛选完整。
3. 最小尺寸下卡片底部四个操作按钮完整。
4. 底部始终存在固定实色区域。
5. 卡片在底边前渐隐，不出现直线硬切。
6. 最后一张卡片可完整滚动到渐变区域上方。
7. 放宽、缩窄、隐藏和重新显示后布局保持一致。
8. 快速关闭防护继续生效。

## 发布判断

V13 仅供真机验证。视觉和交互全部通过后，才把相同逻辑正式写入现有 `ch_08_window.js`、`ch_11_filter.js` 并更新标准清单。
